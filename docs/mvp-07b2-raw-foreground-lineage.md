# MVP-07B2 — Raw foreground context eligibility

Fourth bounded increment, based on main `7e18dfe`. The previous three slices protected historical response fences, summary/episode ranges, and cognitive jobs. Recent raw messages and delivered follow-ups were still direct model inputs even when Memory superseded their source.

## Contract

- Reuse the exact Memory eligibility predicate used by summary/cognition: explicit reports, known Memory revisions, disputes, record status/privacy/expiry. No semantic guesses or broad suppression of unowned speech. The SQL counterpart is parity-tested with the existing inline policy; no change to earlier summary/cognition eligibility plans.
- Select the existing recent turn window, in sequence order. Mask known ineligible older user messages and their anchored assistant bodies; mask follow-ups whose original request or delivery anchor is ineligible, preserving delivery position. The latest authenticated input is never masked, including a correction or disputed report. If initially ineligible, the reply can be delivered but is not reusable as a derived assistant body.
- Preserve current ordinary assistant text. A response with raw-only lineage carries the union of its visible prior response dependencies; broad historical/Relationship/legacy-fenced bodies remain omitted as before. Cap the possible raw source set at 128 IDs, prioritize raw user anchors and newest replies/follow-ups, omit a body rather than truncate its dependency set. Actual retained messages and the bounded current-conversation grounding candidates contribute to the fence. No copied text or transitive graph.
- Migration 0060 stores immutable exact source IDs and reusability for full foreground model-context responses, separately from broad response lineage. Current eligible anchor is included. Check the source set at the end of response commit under the existing shared historical-revision lock, after normal owner/event writes. A concurrent invalidation rolls back response, receipt and events; the existing single stale-context retry applies. No inference under locks. Canonical entity-report owner writes remain isolated from raw-context read fencing; deterministic tool guard omits an ineligible preceding user message.
- At replay, offers, ACK and speech, use the existing response boundary to check exact dependencies under the scope lock. Metadata readiness/status includes the new raw lineage. Unrelated Memory revisions alone do not invalidate raw-only responses. Existing broad fences remain conservative.
- Summary/cognition/episode-source projection may reuse a raw-derived assistant body only when all its dependencies fit inside that range and remain eligible. Otherwise omit the body, rather than silently lose dependencies from the existing summary/cognitive source set. No watermark rewind.

## Limitations

This is bounded raw-message lineage, not a complete provenance graph. Pre-0060 responses without an existing broad fence are marked legacy-unbound, excluded from derived reuse and denied replay. Existing broad-fenced responses retain their prior contract. No guessed backfill or deletion; this deliberately sacrifices replay of old ordinary/direct responses with unknown input lineage. Owner-specific entity/Relationship invalidation beyond the shared exact Memory predicate, active dialogue/intent and other derived copies, canonical route lineage, tool delivery revocation, non-raw optional retrieval, physical erasure and response invalidation after already-sent external bytes remain separate. A whole assistant body can be omitted when any of its dependencies becomes stale, and long conversations may hit the 128-source budget. Raw history source content remains stored. No changes to selection, domain authority, task or goal execution. Query plans and latency need measurement, especially long histories.
