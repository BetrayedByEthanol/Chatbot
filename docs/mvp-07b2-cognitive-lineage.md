# MVP-07B2 — Cognitive reflection and intention lineage

Third bounded increment after PR #133, based on main `4d4bbf5` (includes the predictive user-modeling roadmap). Cognitive reflections are model interpretations, not verified evidence or permission to act. A pass can see more inputs than its single cited turn, including historical episode candidates for optional pattern proposals.

## Contract

- Reuse the exact Memory-owned source eligibility from summary lineage. Keep range positions and watermark; omit known ineligible user text and its assistant body, and never permit a proposal to cite an omitted input. Scheduling readiness remains independent of the model projection.
- Migration 0059 persists the bounded eligible turn IDs (at most 16), all supplied episode IDs and their exact existing snapshot hashes (at most six), and raw projection digest on the existing cognitive job. All reflections and intentions from that pass share the set. Host-derived, not model supplied. Immutable after commit; legacy unknown dependency sets are not guessed and fail closed at cognitive reads. Historical receipts and stored interpretation records remain.
- Recheck source projection and supplied episode snapshots before writes and under the existing historical revision lock after domain/event and optional pattern writes. Revalidate P0 lease and authority. If a supplied episode changes, roll back the entire pass, even if a reflection cites a different turn; the model saw the episode. Unrelated revision changes do not invalidate exact current reflection dependencies. Existing conservative optional pattern admission fence remains independent and can discard a pattern without discarding otherwise current reflections. No model I/O under locks.
- Scope all reads to user/instance/conversation. Reflection eligibility includes the entire input set and matching episode payloads, including parent summary eligibility. Apply at diagnostic proposal listing and goal-related hypothesis context. The latter captures the existing historical fence before the hypothesis read and persists it with the response if a hypothesis is actually included. Entity-owner writes do not receive hypotheses because they cannot share this read fence. Review updates/deletes bump the historical revision; new proposals do not invalidate prior responses.
- Add a read-only eligible intention proposal view (unexpired, unasked, PROPOSED, eligible parent reflection). No automatic intention admission, speaking, goal mutation or scheduling. The existing attention and response scheduler constraints still apply. Ineligible proposals remain stored with their original status; no retroactive cancellation or watermark rewind. Replay returns historical commit counts, not stale content.

## Limitations and verification

Exact Memory revisions/explicit reports and existing episode snapshot rules only; unowned semantic corrections, ordinary foreground history, transitive assistant copies, full entity/relationship source coverage, and pattern-derived outputs' complete prompt dependencies remain open. Legacy reflection content is omitted from eligible reads even when benign. No new retention policy, deletion, or deployment approval. The prior PostgreSQL runtime increased from about six to ten minutes; the added joins require plan/performance review. Existing 30-day hypothesis age rule is not a new persistent response time dependency. Intention activation is not implemented.

Regression cases cover raw-source correction/expiry before commit, fresh masked inference, invalid citation, correction after commit, unaffected scopes, historical episode mutation before/after commit, intention expiry/already-asked eligibility, legacy omission, and foreground hypothesis fencing. Existing context fixtures now supply explicit synthetic committed lineage; no backfill of real legacy jobs. No local PostgreSQL runtime available; static review only, CI pending. US-117/118 remain partial.
